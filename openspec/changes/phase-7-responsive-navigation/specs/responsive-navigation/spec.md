## Purpose

文書ツリー、本文、ページ内見出しを画面幅に応じて読みやすく配置し、狭い画面でもキーボードやタッチ操作で文書を安全に選択できるようにする。

## ADDED Requirements

### Requirement: 閲覧レイアウトが利用可能幅に適応する

yomは、1,200px以上で文書ツリー、本文、ページ内見出しの3ペインを表示し、900px以上1,200px未満で文書ツリーと本文の2ペインを表示し、900px未満で本文を主領域として表示しなければならない（SHALL）。利用者が保存済みのサイドバー幅を持つ場合も、本文の最低幅を優先しなければならない（MUST）。

#### Scenario: 広いデスクトップで3ペインを表示する

- **WHEN** ビューポート幅が1,440pxでページ内見出し表示が有効である
- **THEN** 文書ツリー、本文、ページ内見出しが同時に表示される

#### Scenario: タブレット幅で本文幅を確保する

- **WHEN** ビューポート幅が1,024pxで、保存済みサイドバー幅が最大値である
- **THEN** ページ内見出しは非表示になり、文書ツリーと本文が表示され、本文側のレイアウト領域が640px以上になる

#### Scenario: 狭い画面で本文を主領域にする

- **WHEN** ビューポート幅が390pxで文書ナビゲーションが閉じている
- **THEN** 文書ツリーは表示されず、本文の位置と幅はナビゲーションを開く前後で変化しない

### Requirement: モバイル文書ナビゲーションを開閉できる

900px未満では、yomは開閉ボタンから文書ツリーを本文に重なるドロワーとして表示しなければならない（SHALL）。開閉状態は`aria-expanded`で通知し、閉じているドロワーは操作対象になってはならない（MUST）。

#### Scenario: 開閉ボタンでナビゲーションを開く

- **WHEN** 利用者がモバイル文書ナビゲーションの開閉ボタンを操作する
- **THEN** 文書ツリーと背景レイヤーが本文の上に表示され、開閉ボタンの`aria-expanded`が`true`になる

#### Scenario: Escapeでナビゲーションを閉じる

- **WHEN** モバイル文書ナビゲーションが開いている状態で利用者が`Escape`を押す
- **THEN** ナビゲーションが閉じ、開閉ボタンの`aria-expanded`が`false`になり、開閉ボタンへフォーカスが戻る

#### Scenario: 背景クリックでナビゲーションを閉じる

- **WHEN** モバイル文書ナビゲーションが開いている状態で利用者が背景レイヤーをクリックする
- **THEN** ナビゲーションが閉じ、開閉ボタンへフォーカスが戻る

#### Scenario: 文書選択後にナビゲーションを閉じる

- **WHEN** モバイル文書ナビゲーションから文書を選択する
- **THEN** 選択した文書が表示され、ナビゲーションが閉じ、開閉ボタンへフォーカスが戻る

### Requirement: ナビゲーションの役割を区別できる

yomは、文書を選ぶナビゲーションと表示中ページの見出しを選ぶナビゲーションに異なる表示名およびアクセシブルネームを与えなければならない（SHALL）。

#### Scenario: 支援技術で二つのナビゲーションを識別する

- **WHEN** 文書ツリーとページ内見出しが同時に表示される
- **THEN** 利用者はそれぞれを「Documents」と「On this page」として識別できる

### Requirement: 対応幅でページ全体が横方向にあふれない

yomは、320pxから1,440pxまでの対応幅において、長いパス、コード、表、画像を含む文書でもページ全体に意図しない横スクロールを発生させてはならない（MUST）。横スクロールが必要な文書要素は、その要素の領域内でスクロール可能にしなければならない（SHALL）。

#### Scenario: 320px幅で長い内容を表示する

- **WHEN** 320px幅で長いパス、コード、表、画像を含む文書を表示する
- **THEN** 文書要素は読める方法で折り返すか要素内でスクロールし、ページ全体のスクロール幅はビューポート幅を超えない

### Requirement: devとstatic buildで同じレスポンシブ動作を提供する

yomは、サーバー固有機能を除き、devとstatic buildで同じブレークポイント、表示状態、モバイル文書ナビゲーション操作を提供しなければならない（SHALL）。

#### Scenario: 主要幅でdevとstatic buildを比較する

- **WHEN** 同じ文書を390px、1,024px、1,440pxでdevとstatic buildに表示する
- **THEN** ペインの表示状態、主要な配置、モバイルナビゲーション操作が一致する
