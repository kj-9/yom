## Context

現在のUIには900px以下の開閉ボタンと`nav-open`状態が存在するが、サイドバーは通常フロー内で開くため本文を押し下げ、閉じ方は開閉ボタンに限られている。`src/site/styles.css`の本文とページ内見出しは画面幅に関係なく2列を基本とし、保存済みサイドバー幅は1,024px時の本文領域を侵食できる。

site engine評価の結果、Vite + Preact + `preact-render-to-string`を採用し、`migrate-site-to-vite-preact`で命令的DOM処理を共有component、reducer、prerender/hydrationへ移す。本変更はそのmigration完了後のcomponent構造を前提とし、実装開始前に実際の`Shell`、`DocumentTree`、`Outline`、共有stateとの整合を再確認する。

## Goals / Non-Goals

**Goals:**

- 移行後の共有Preact shellを保ち、CSSを中心に3段階のレイアウトを構成する。
- モバイルナビゲーションの状態遷移を共有reducerへ集約し、入力方法にかかわらずARIA状態とフォーカスを同期する。
- 現在のサイドバー幅保存を維持しながら、利用可能な本文幅を優先する。
- devとstatic buildを同一E2Eシナリオで検証する。

**Non-Goals:**

- サイト設定やローカル保存形式を追加・変更しない。
- 表示設定カード、検索結果、ページ内見出しのモバイル専用UIは再設計しない。
- DOMをdev用とstatic build用に分岐させない。

## Decisions

### Preact migration完了を実装の前提条件にする

`migrate-site-to-vite-preact`を完了した後に本変更を再レビューする。mobile drawerは移行後の`Shell`と`DocumentTree`を拡張し、開閉状態は共有reducerへ追加する。migration前の命令的DOMへ先行実装する案は、component化の際の廃棄作業と二重保守を増やすため採用しない。

### CSSの2つのブレークポイントで3段階を表現する

1,200px未満では`.reader-shell`からページ内見出し列を外し、900px未満では`.layout`を本文主体にする。JavaScriptでビューポート幅を監視してDOMを再生成する案は、リサイズ時の状態同期とdev/static差異を増やすため採用しない。

### 中間幅では実効サイドバー幅を本文最低幅から制限する

保存値`--sidebar-width`自体は変更せず、900px以上1,200px未満のグリッド列だけを、ビューポートから本文側640pxとリサイザー幅を差し引いた値以下へ制限する。保存値を書き換える案は、広い画面へ戻った時に利用者の好みを失うため採用しない。

### モバイルサイドバーを固定オーバーレイドロワーにする

900px未満ではサイドバーを固定配置し、独立した背景レイヤーとともに本文の上へ表示する。開閉時に本文のグリッドや余白を変えず、開いている間は背景コンテンツを操作対象外にし、ページスクロールを抑止する。サイドバーを通常フローで展開する現方式は本文位置が変わるため置き換える。

### 開閉処理を単一のreducer transitionへ集約する

開閉ボタン、`Escape`、背景クリック、文書選択は同じreducer actionへ正規化し、`nav-open`、`aria-expanded`、背景レイヤー、スクロール抑止を同時に更新する。閉じる操作ではcomponentのrefを通して開閉ボタンへフォーカスを戻す。画面幅が900px以上へ変わった場合も状態を解除し、非表示のモバイルUIへフォーカスが残らないようにする。

### 既存E2Eにレスポンシブ専用シナリオを追加する

390px、1,024px、1,440pxでペインの表示と境界を数値で検証し、390pxではすべての閉じ方とフォーカス復帰を検証する。devとstatic buildは同じヘルパーで検証し、主要状態のスクリーンショットを比較する。色やフォント描画だけに依存する全面スナップショットではなく、配置のアサーションを合否の中心にする。

## Risks / Trade-offs

- [保存済みの広いサイドバー幅が中間幅で見かけ上縮む] → 保存値は維持し、広い画面へ戻ると元の幅を復元する。
- [固定ドロワーの重なり順が設定カードやスキップリンクと競合する] → モバイルレイヤーのz-index階層をまとめ、スキップリンクを最上位に保つ。
- [背景の操作抑止やスクロール抑止が閉じた後も残る] → 状態更新関数と幅変更時のクリーンアップをE2Eで検証する。
- [長い表やコードの収まり方を変えることでデスクトップ表示が回帰する] → オーバーフロー制御は文書要素へ限定し、1,440pxの既存表示も比較する。

## Migration Plan

まず`migrate-site-to-vite-preact`を完了し、本設計とtasksを実際のcomponent、reducer、dev/static shared renderingへ合わせて再レビューする。その後、`Shell`と`DocumentTree`へ背景レイヤーと識別可能なナビゲーション名を追加し、CSSとreducer actionを段階的に実装する。公開設定や保存キーの移行は不要。回帰時は新しい背景レイヤー、mobile navigation action、追加ブレークポイントを一単位で戻せる。
